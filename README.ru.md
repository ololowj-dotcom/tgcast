> `tgcast.exe`: меню проведёт по настройке и отправке. Подробности в разделе [Установка](#установка).

**Рассылка по базе ваших Telegram-чатов.** Вы ведёте базу (простой список) своих каналов и групп в текстовом файле,
пишете одно сообщение, а tgcast публикует его в каждый чат базы от вашего Telegram-аккаунта, по одному, с безопасными
паузами и лимитами и никогда не дважды в один чат. База может быть любой длины: она обрабатывается за несколько
запусков.

Типичные задачи: объявить о событии, релизе или акции сразу во всех сообществах, которые вы ведёте; опубликовать одно
и то же обновление в нескольких группах, которыми вы управляете; поделиться новостью с партнёрскими чатами, которые
согласились её получать.

*[Read in English](README.md)*

## Как это работает, простыми словами

1. **Вы входите один раз.** tgcast спрашивает номер телефона и код, который присылает Telegram, как при входе с нового
   устройства. Дальше программа действует как **ваш аккаунт** и хранит вход в файле `tgcast.session`.
2. **Вы даёте ей два файла:** текст сообщения и список чатов.
3. **Она проверяет каждый чат:** состоите ли вы в нём и разрешено ли вам там писать.
4. **Вы видите план:** в какие чаты уйдёт сообщение, какие пропущены и почему, точный текст. И подтверждаете.
5. **Она отправляет по одному**, со случайными паузами, и записывает каждую отправку в файл истории, чтобы ничего не
   уходило дважды.

## Что tgcast делает и чего не делает

| Делает | Не делает |
|---|---|
| Пишет от вашего аккаунта в чаты, где вы **уже участник** и вам разрешено писать | Не вступает в чаты за вас |
| Публикует в канале, только если вы админ с правом публикации | Не пишет отдельным людям (личные сообщения) |
| Пропускает чаты, куда нельзя писать, и объясняет почему | Не собирает участников и не ищет чаты сама |
| Делает паузы между сообщениями, отдыхает между пачками, останавливается на лимите за запуск | Не отправляет быстрее и больше, чем заданные вами лимиты |
| Останавливает запуск, если Telegram сообщает об ограничении аккаунта | Не работает с несколькими аккаунтами и не скрывает отправителя |
| Не пишет в один чат повторно в течение паузы между повторами (по умолчанию 24 часа) | Не обходит правила Telegram и капчи |

tgcast нужен для объявлений в сообществах, **которые вы ведёте или где вам разрешено писать**: свои каналы и группы,
партнёрские чаты по договорённости. Массовые нежелательные сообщения нарушают правила Telegram и ведут к ограничению
аккаунтов; лимиты выше нужны, чтобы инструмент не превратился в это.

## Какой аккаунт использовать

Программа входит в настоящий аккаунт, поэтому весь риск ложится на него. Telegram может ограничить аккаунт, который
публикует много одинакового текста, особенно в чаты, которые об этом не просили.

- **Свои каналы и группы:** подойдёт основной аккаунт.
- **Чужие чаты (партнёры, сообщества):** используйте **отдельный аккаунт**, а не основной, и только там, где
  объявления разрешены.

## Установка

**Windows, самый простой способ (Python не нужен):** скачайте `tgcast-windows.zip` из
[последнего релиза](https://github.com/ololowj-dotcom/tgcast/releases/latest), распакуйте, положите `tgcast.exe` в
пустую папку под вашу рассылку и **дважды щёлкните по нему**. Откроется меню: 1 настройка, 2 проверка, 3 предпросмотр,
4 отправка, 5 история. Всё описанное ниже работает так же: меню просто запускает эти команды за вас. Windows
SmartScreen может предупредить, что программа не подписана: нажмите «Подробнее» -> «Выполнить в любом случае». Файл
собирается из этого репозитория в GitHub Actions, а `SHA256SUMS.txt` позволяет его проверить.

**Через Python (любая система):**

```bash
pip install git+https://github.com/ololowj-dotcom/tgcast
```

Нужен Python 3.9 или новее. На Windows сначала установите Python с python.org (отметьте «Add to PATH»), затем
выполните команду в PowerShell. Запуск `tgcast` без аргументов открывает то же меню.

## Шаг за шагом

1. **Получите api_id и api_hash** (один раз): зайдите на https://my.telegram.org, откройте *API development tools*,
   создайте приложение (любое название) и скопируйте два значения. Они идентифицируют ваше приложение для Telegram,
   храните их в тайне.
2. **Создайте папку** под объявление и запустите мастер внутри неё:

   ```bash
   mkdir my-announcement && cd my-announcement
   tgcast setup
   ```

   Мастер спросит api_id, api_hash и номер телефона в международном формате (`+7...`). Код входа Telegram пришлёт вам
   **в приложении Telegram** (сообщение от «Telegram»); введите его. Если у аккаунта включена двухэтапная проверка,
   мастер спросит и пароль. Затем он создаст `tgcast.toml`, `message.md`, `targets.txt`, `.env` и `.gitignore`,
   который не даст секретам попасть в git.
3. **Напишите сообщение** в `message.md`. Подстановки вроде `{title}` заполняются для каждого чата (см. ниже).
4. **Перечислите чаты** в `targets.txt`, по одному на строку: `@username`, ссылка `t.me/...` или числовой id чата.
   Текст после `#` игнорируется.
5. **Проверка:** `tgcast check` покажет каждый чат и можно ли вам туда писать.
6. **Предпросмотр:** `tgcast send --dry-run` покажет план и точный текст для первого чата. Ничего не отправляется.
7. **Отправка:** `tgcast send` снова покажет план, спросит «Send to N chat(s) now?» и только после подтверждения начнёт.

Как узнать id чата: откройте чат в Telegram Web (web.telegram.org); число после `#` в адресной строке и есть id. У
каналов и супергрупп оно начинается с `-100`. Если сомневаетесь, используйте `@username` чата или ссылку `t.me`.

## Текст сообщения

`message.md` - обычный текст в формате из `parse_mode` (по умолчанию Markdown: `**жирный**`, `__курсив__`,
`[ссылка](https://example.com)`). Для каждого чата подставляются:

| Подстановка | Значение |
|---|---|
| `{title}` | название чата |
| `{username}` | его @username (пусто, если его нет) |
| `{id}` | числовой id |
| `{date}` | сегодняшняя дата, `ГГГГ-ММ-ДД` |

Для фигурных скобок как обычного текста пишите `{{` и `}}`. Чтобы отправить картинку или файл вместе с текстом,
добавьте `attachment = "banner.jpg"` в раздел `[message]` файла `tgcast.toml`; текст станет подписью.

## Сколько это занимает

С настройками по умолчанию пауза между сообщениями в среднем 40 секунд, плюс 5 минут отдыха после каждого 10-го
сообщения, а за запуск уходит не больше 20 чатов:

| Чатов за запуск | Время |
|---|---|
| 5 | около 3 минут |
| 10 | около 6 минут |
| 20 | около 17 минут |

`tgcast send` показывает оценку до подтверждения. Не закрывайте окно, пока идёт отправка; Ctrl+C останавливает её
аккуратно, а всё уже отправленное остаётся в истории.

## Большая база чатов

База - это файл `targets.txt`: один чат на строку, строк сколько угодно. За один запуск уходит не больше
`max_per_run` чатов (по умолчанию 20), остальная база ждёт. Просто запустите `tgcast send`
позже: чаты, которые уже получили сообщение, пропускаются, берутся следующие.

**Важно для разового объявления:** защита «не дважды» действует `cooldown_hours` (по умолчанию 24 часа). Если ваш
список обрабатывается несколько дней, чаты первого дня на второй день снова становятся доступными. Для разовой
кампании поставьте длинную паузу в `tgcast.toml`, например `cooldown_hours = 720` (30 дней), и каждый чат получит
сообщение один раз.

Чтобы не сидеть за компьютером, `--yes` отключает вопрос о подтверждении (`tgcast send --yes`), а запуск можно
поставить в Планировщик заданий (Windows) или cron (Linux/macOS). `tgcast send --at "2026-10-01 10:00"` подождёт до
указанного местного времени.

## Настройки безопасности

Всё в `tgcast.toml`, раздел `[limits]`:

| Параметр | По умолчанию | Что значит |
|---|---|---|
| `delay_min`, `delay_max` | 20, 60 | случайная пауза в секундах между двумя сообщениями |
| `batch_size`, `batch_pause` | 10, 300 | после стольких сообщений отдыхать столько секунд |
| `max_per_run` | 20 | не отправлять больше за один запуск (жёсткий потолок 500) |
| `cooldown_hours` | 24 | не писать в один чат дважды за это время |
| `flood_wait_max` | 300 | если Telegram просит ждать дольше, запуск останавливается |
| `retries` | 2 | попыток после короткого ожидания или сбоя сети |

Ошибки в настройках объясняются с подсказкой (`unknown setting 'delay_mn' (did you mean 'delay_min'?)`).

## Команды

| Команда | Назначение |
|---|---|
| `tgcast setup` | вход в аккаунт и создание файлов |
| `tgcast check` | проверка всего и список чатов, куда можно писать (код выхода 2, если куда-то нельзя) |
| `tgcast send` | отправка; `--dry-run` только предпросмотр, `-y` без подтверждения, `--force` игнорировать паузу между повторами, `--limit N`, `--at "2026-10-01 10:00"` |
| `tgcast status` | последние запуски и сколько чатов уже получили сообщение |

Коды выхода `send`: `0` всё выполнено, `2` часть чатов не удалась, `3` запуск остановлен (ограничения Telegram, потеря
сессии, Ctrl+C), `1` ошибка настроек. Дополнительно: раздел `[report]` в `tgcast.toml` может дописывать каждый результат
в CSV-файл (`csv = "report.csv"`) и присылать сводку в «Избранное» (`notify_self = true`).

## Если что-то пошло не так

| Что вы видите | Что это значит и что делать |
|---|---|
| Код входа не приходит | Загляните в приложение Telegram: чат «Telegram» (не SMS). Подождите минуту и запустите `tgcast setup` снова |
| `no such chat or username` | Проверьте написание. У приватных чатов нет username: используйте числовой id, и вы должны быть участником |
| `you are not a member of this chat` | Сначала вступите в чат сами: tgcast никуда не вступает |
| `you are restricted in this group` / `sending is disabled for members` | Чат не даёт вам писать. Попросите админа или уберите чат из списка |
| `Telegram asks to wait Ns` | Лимит частоты Telegram. Короткие ожидания программа пережидает сама; дольше `flood_wait_max` останавливает запуск: попробуйте позже |
| `PeerFlood` / «аккаунт ограничен» | Telegram ограничил аккаунт. tgcast останавливается. Не повторяйте сразу: проверьте аккаунт через @SpamBot в Telegram, подождите день-два и уменьшите объём |
| `the Telegram session is no longer valid` | Вход завершён (или аккаунт заблокирован). Запустите `tgcast setup` снова |
| `already sent ... (cooldown ...)` | Чат недавно получил сообщение. Подождите, измените `cooldown_hours` или осознанно используйте `--force` |

## Ваш вход в аккаунт

`tgcast.session` **это вход в ваш Telegram**. Любой, у кого он есть, может действовать от вашего имени: никому не
передавайте и не коммитьте (созданный `.gitignore` его исключает). Если файл утёк, завершите эту сессию в Telegram:
Настройки -> Устройства.

## Разработка

```bash
git clone https://github.com/ololowj-dotcom/tgcast && cd tgcast
python -m venv .venv && . .venv/bin/activate
pip install -e ".[dev]"
pytest && ruff check src tests
```

Тесты не обращаются к Telegram: его заменяет управляемая заглушка, включая FloodWait, PeerFlood, закрытые чаты и сбои
сети, а слой Telethon проверяется на поддельном клиенте с настоящими исключениями Telethon. CI идёт на Python 3.9-3.13.
