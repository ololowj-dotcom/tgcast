# tgcast

[![CI](https://github.com/ololowj-dotcom/tgcast/actions/workflows/ci.yml/badge.svg)](https://github.com/ololowj-dotcom/tgcast/actions/workflows/ci.yml)
![Python 3.9+](https://img.shields.io/badge/python-3.9%2B-blue)
![License MIT](https://img.shields.io/badge/license-MIT-green)

**Аккуратная рассылка объявлений в ваши Telegram-каналы и группы.** Вы перечисляете чаты, пишете текст, смотрите
предпросмотр, а tgcast публикует его от вашего аккаунта: неторопливо, в рамках лимитов и никогда не дважды в один чат.

*[Read in English](README.md)*

- **Сначала посмотрите.** `tgcast send --dry-run` показывает каждый чат, можно ли вам там писать, и точный текст.
- **Учитывает права.** Для каждого чата проверяет, что вы участник и вам разрешено писать (или вы админ канала), а
  остальные пропускает с причиной, а не падает на полпути.
- **Не повторяется.** Файл истории помнит, куда ушло сообщение; в тот же чат повторно не пишет `cooldown_hours` часов
  (по умолчанию 24).
- **Медленно намеренно.** Случайные паузы, отдых после каждой пачки, жёсткий лимит за запуск, подчинение просьбам
  Telegram подождать (FloodWait).
- **Останавливается, когда нужно.** Если Telegram сообщает об ограничении аккаунта или просит ждать очень долго,
  запуск завершается с объяснением, что делать.
- **Удобно.** `tgcast setup` входит в аккаунт и создаёт файлы. Персонализация текста (`{title}`, `{date}`), картинка,
  CSV-отчёт, сводка в «Избранное», `--at` для отправки позже.

## Ответственное использование

tgcast нужен для объявлений в сообществах, **которые вы ведёте или где вам разрешено писать**: свои каналы, свои группы,
партнёрские чаты по договорённости. Ограничения заложены намеренно: программа не вступает в чаты, не пишет отдельным
людям, не собирает участников и работает с одним аккаунтом. Массовые нежелательные сообщения нарушают правила Telegram
и приводят к ограничению аккаунтов; для этого инструмент не предназначен, а лимиты нужны, чтобы так и оставалось.

## Установка

```bash
pip install git+https://github.com/ololowj-dotcom/tgcast
```

Нужен Python 3.9 или новее. На Windows сначала установите Python с python.org (отметьте «Add to PATH»), затем
выполните команду в PowerShell.

## Быстрый старт

1. Один раз получите **api_id** и **api_hash** на https://my.telegram.org (API development tools).
2. Создайте папку под объявление и запустите мастер внутри неё:

   ```bash
   mkdir my-announcement && cd my-announcement
   tgcast setup
   ```

   Он спросит api_id, api_hash и номер телефона, выполнит вход (код придёт в Telegram) и создаст `tgcast.toml`,
   `message.md`, `targets.txt`, `.env` и `.gitignore`, который не даст секретам попасть в git.
3. Впишите текст в `message.md`, а чаты в `targets.txt` (по одному `@username`, ссылке t.me или id чата на строку).
4. Проверьте, посмотрите, отправьте:

   ```bash
   tgcast check            # в какие чаты вам можно писать?
   tgcast send --dry-run   # план и точный текст, ничего не отправляется
   tgcast send             # спросит подтверждение и отправит
   ```

## Текст сообщения

`message.md` - обычный текст в формате из `parse_mode` (по умолчанию Markdown). Для каждого чата подставляются:

| Подстановка | Значение |
|---|---|
| `{title}` | название чата |
| `{username}` | его @username (пусто у приватных чатов) |
| `{id}` | числовой id |
| `{date}` | сегодняшняя дата, `ГГГГ-ММ-ДД` |

Для фигурных скобок как обычного текста пишите `{{` и `}}`. Картинку или файл добавляет `attachment = "banner.jpg"` в
разделе `[message]`.

## Лимиты и защита

Всё в `tgcast.toml`, раздел `[limits]`:

| Параметр | По умолчанию | Что значит |
|---|---|---|
| `delay_min`, `delay_max` | 20, 60 | случайная пауза в секундах между двумя сообщениями |
| `batch_size`, `batch_pause` | 10, 300 | после стольких сообщений отдыхать столько секунд |
| `max_per_run` | 20 | не отправлять больше за один запуск (остальное ждёт следующего) |
| `cooldown_hours` | 24 | не писать в один чат дважды за это время |
| `flood_wait_max` | 300 | если Telegram просит ждать дольше, запуск останавливается |
| `retries` | 2 | попыток после короткого ожидания или сбоя сети |

Ошибки в настройках объясняются с подсказкой (`unknown setting 'delay_mn' (did you mean 'delay_min'?)`).

## Команды

| Команда | Назначение |
|---|---|
| `tgcast setup` | вход в аккаунт и создание файлов |
| `tgcast check` | проверка всего и список чатов, куда можно писать (код выхода 2, если куда-то нельзя) |
| `tgcast send` | отправка; `--dry-run` только предпросмотр, `-y` без подтверждения, `--force` игнорировать паузу между повторами, `--limit N`, `--at "2026-10-01 10:00"` |
| `tgcast status` | последние запуски и сколько чатов уже получили сообщение |

Коды выхода `send`: `0` всё выполнено, `2` часть чатов не удалась, `3` запуск остановлен (ограничения Telegram, потеря
сессии, Ctrl+C), `1` ошибка настроек.

## Ваш вход в аккаунт

`tgcast.session` **это вход в ваш Telegram**. Любой, у кого он есть, может действовать от вашего имени: никому не
передавайте и не коммитьте (созданный `.gitignore` его исключает). Если файл утёк, завершите сессию в Telegram:
Настройки -> Устройства.

## Разработка

```bash
git clone https://github.com/ololowj-dotcom/tgcast && cd tgcast
python -m venv .venv && . .venv/bin/activate
pip install -e ".[dev]"
pytest && ruff check src tests
```

Тесты не обращаются к Telegram: его заменяет управляемая заглушка, включая FloodWait, PeerFlood, закрытые чаты и сбои
сети, а слой Telethon проверяется на поддельном клиенте с настоящими исключениями Telethon. CI идёт на Python 3.9-3.13.
